Deploy to MilesWeb without exposing your source code

A step-by-step guide to cloning public and private GitHub repositories onto MilesWeb cPanel hosting with SSH deploy keys, publishing only the built files to public_html, and testing that nobody can download your .git folder.

Most cPanel tutorials tell you to clone your repository straight into public_html. That works, and it also publishes your .git folder, which holds every file and every past commit, including anything you once committed by mistake. Tools that scan the internet for /.git/config run all day.

This guide keeps the repository in your private home directory and copies only the files that belong on the web into public_html. It is written for MilesWeb shared hosting (cPanel), but every step works on any cPanel host.

02What cPanel is, and what MilesWeb gives you

cPanel is the web control panel MilesWeb puts on top of a Linux hosting account. You log in at https:///cpanel (or through the MilesWeb client area) and get tools for files, domains, email, databases, and, the ones we need here:

  • File Manager: a browser view of your home directory.
  • Terminal (Advanced → Terminal): a shell in your browser. It only appears when Shell Access is enabled on your plan. If you do not see it, ask MilesWeb support to enable SSH.
  • SSH Access (Security → SSH Access): manage keys for logging in from your own computer.
  • Git Version Control (Files → Git Version Control): clone a repository, pull updates, and run a deployment with one click.
  • Domains: shows the document root (the folder a domain serves) for your main domain, subdomains and addon domains.

Your account is a Linux user with a home directory. Only one folder in it is served to the internet:

Anything inside public_html (or inside a subdomain's document root) can be requested by anyone. Anything outside it cannot, as long as no web folder links to it.

03Where the code lives

The rule for the whole guide:

Source outside, output inside.

Clone every repository into /<repo>, which is outside the web root. Copy only the folder that holds your built or static site (for this site, site/) into the web root. Never clone into public_html, and never copy the repository root.

This is exactly how this site is already set up. Its DEPLOY.md clones the repository to repositories/mdism, and its .cpanel.yml copies only site/ into public_html. This guide adds the parts DEPLOY.md does not cover: SSH deploy keys for private repositories, more than one repository, and tests.

The build step happens before the copy.

If a project needs a build (React, Vite, Svelte, Hugo and so on), build it on your computer or in GitHub Actions and commit the output folder (for example dist/) on a deploy branch, or build it on the server in the .cpanel.yml tasks if the server has the tools. Either way, the source folder you set for that repository is the one that gets copied.

Option B: SSH from your own computer

In cPanel → Security → SSH Access → Manage SSH Keys → Import Key, give it a name, paste the public key you just printed, and import. Then click Manage next to the key and Authorize it.

06Create one deploy key per repository

A deploy key is an SSH key attached to a single GitHub repository instead of your account. If the hosting account is ever compromised, the attacker gets read access to that one repository, not your whole GitHub account. GitHub does not let you attach the same deploy key to two repositories, which is why each repository gets its own key.

Run this once per repository in the cPanel Terminal. The key has no passphrase because cPanel has to use it without you typing anything; it is read-only, which is what makes that acceptable.

Then add each printed public key to GitHub. The link opens the right page for each repository:

  1. Title: something you will recognise later, such as MilesWeb .
  2. Key: paste the whole line that starts with ssh-ed25519.
  3. Leave Allow write access unticked. The server only ever needs to pull.
Public repositories

A public repository can be cloned over HTTPS with no key at all, which is what DEPLOY.md does today. Setting up a deploy key for it anyway costs two minutes and means nothing breaks if you later make the repository private. One exception: mdism/mdism must stay public, because GitHub only shows a profile README from a public repository.

07Give each repository a Host alias in ~/.ssh/config

Every GitHub repository lives at the same address, github.com. If you have two keys, SSH needs to know which key to offer for which repository. A Host alias solves that: you invent a name (for example github-mdism), point it at github.com, and pin it to one key. Then you clone from the alias instead of from github.com.

09Publish only the built files with .cpanel.yml

cPanel's Deploy HEAD Commit button runs the tasks in a file called .cpanel.yml at the root of the repository. Put this file in the repository on your computer, commit it and push it. Each task is one shell command; the copy line is what keeps your source private, because it copies the contents of the source folder and nothing else.

Already in place for this site.

The repository's existing .cpanel.yml already copies site/. to public_html. Its path starts with //home/; the double slash works on Linux, and the version above simply writes it with one slash and adds a mkdir so a new folder target also works.

  • Use spaces, not tabs, in YAML.
  • Deploy needs a clean working tree on the server: if someone edited files inside the clone, the Deploy button stays disabled.
  • cp adds and overwrites, it never deletes. When you remove or rename a page, delete the old copy from public_html in File Manager.
  • Never set the source folder to . (the repository root): that copies .git, README files and scripts into the web root.

10When you have more than one repository

Everything above already loops over every repository in your settings. The rules that keep several repositories from clashing:

  1. One key per repository: ~/.ssh/deploy_<repo>. GitHub rejects a deploy key that is already used on another repository ("Key is already in use").
  2. One Host alias per repository: github-<repo>, each pinned to its own key with IdentitiesOnly yes.
  3. One clone folder per repository: /<repo>, all outside the web root.
  4. One publish target per repository: the main site goes to public_html, others to a sub-folder (public_html/app) or to a subdomain's own document root. Two repositories copying into the same folder will overwrite each other's files.
  5. A clone URL that uses the alias: git@github-<repo>:owner/repo.git, never plain git@github.com:….

A subdomain for a second project

If a project should live at app., create the subdomain in cPanel → Domains with its document root inside the web root (for example public_html/app) and set that repository's publish target to app. If cPanel puts the document root outside public_html, change the DEPLOYPATH line in that repository's .cpanel.yml to the folder cPanel shows.

11Harden public_html (optional, recommended)

Even with the source outside the web root, it is worth telling the web server to refuse hidden files and to stop listing folders that have no index page. This appends a small block to public_html/.htaccess once; cPanel's own lines in that file stay as they are.

RedirectMatch 404 makes every path that contains a dot-folder or dot-file (/.git/, /.env, /.cpanel.yml) answer "404 Not Found", while /.well-known/ keeps working for SSL certificate renewal. If the site shows a 500 error afterwards, the host does not allow Options in .htaccess: delete that one line.

Watch out

If you ever add a .htaccess file inside your source folder, the deploy copy will overwrite the one in public_html. Put the block above into that file too.

Two more habits: never put secrets (API keys, database passwords, .env files) in the folder you publish, and keep any server-side config files in your home directory, outside the web root.

13Troubleshooting

MessageCause and fix
Permission denied (publickey)The public key is not on that repository's Deploy keys page, the clone URL uses github.com instead of the alias, or the key file is readable by others. Re-run test 1 and the permissions test.
Host key verification failedGitHub's key is not in ~/.ssh/known_hosts. Redo step 5.
Key is already in use (on GitHub)That key is attached to another repository or to your account. Make a new key for this repository (step 6).
ERROR: Repository not foundUsually the right server but the wrong key: the alias is missing IdentitiesOnly yes, or the owner/repo name is misspelled.
Connection timed out on port 22The host blocks outgoing port 22. Tick Reach GitHub over port 443 in the settings, then redo steps 5 and 7.
Deploy HEAD Commit is greyed out.cpanel.yml is missing from the repository root, or the clone on the server has local changes (git status in the clone folder shows them).
Old pages still onlineThe copy never deletes. Remove them from public_html in File Manager.
